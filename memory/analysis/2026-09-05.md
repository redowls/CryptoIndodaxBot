**Reporting-command defect (not a bot bug).** The routine's documented read-only
command calls `broker.get_account()` with no `price_by_symbol`, and equity then
collapses to IDR-cash-only: it printed **Rp328.593**, understating true equity by
the entire Rp165.341 DOT holding — a fake −34% drawdown against the Rp500.861
funding. The trader itself passes marks from the snapshot (`trader.py:185`,
`prices_from_snapshot`) and logs the correct Rp493.934 every hour, so nothing in
the trading path is affected. The digest command needs the marks or it will keep
crying drawdown whenever a position is open. Same trap in reverse for
`trades.json`: it is a dict of `open`/`closed`, not a list — a naive `len()` on
the wrong key reports "0 trades" on a ledger that is fully intact.
