## Headline: the ledger's P&L is fabricated — proven live, root cause found

Reconciling the exchange against `trades.json` today exposed a defect that has
been present since the bot went live on 09-01. **Every entry and exit price in
the ledger is the snapshot 1H close, never the achieved fill.**

Root cause, confirmed by direct read-only API calls:

- `broker.avg_fill_price()` queries `/api/v2/myTrades` with the **bare numeric**
  order id (`"64028789"`). Indodax rejects it:
  `[1109] Invalid parameter 'orderId', invalid orderId format`.
  The real id is **prefixed**: `linkidr-market-64028789`, which returns the fills.
- That `BrokerError` is caught → `avg_fill_price` returns `None` →
  `get_order` falls back to `o.get("price")`, absent on MARKET orders →
  `filled_avg_price = None` → `trader._exit_position` keeps
  `exit_price = price_hint` (the snapshot close, `trader.py:106`) and
  `_enter_position` keeps `entry_price = fill_price or price` (`trader.py:153`).
- Verified: `broker.avg_fill_price("LINK","64028789")` → `None`, while
  `orderId="linkidr-market-64028789"` → 2 fills.
